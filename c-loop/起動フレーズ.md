# 実行手順(構成C)※人間向け

このフォルダをカレントにセッションを開き、`/model opus` にする。実行方法は2つ。

## 方法1: 自動実行(推奨)

```
/run-loop
```

ディスパッチャ(進行係)が `進捗.md` を見ながら、各役割をサブエージェント(独立コンテキスト)として順に起動し、3ループ完了まで回す。異常(役割からの質問・成果物なし等)があれば止まって報告してくるので、人間が対処してから再度 `/run-loop`(進捗.md の続きから再開する)。

工程ごとの記録はディスパッチャが 実行記録.md に自動追記する。人間の仕事は、終了後に `/cost` の値を 実行記録.md に**1回**書き足すことだけ(トークン量はAIが自分で測れないため)。

## 方法2: 手動実行(1工程ずつ確認したいとき・書籍の実演用)

工程ごとに新規セッション(`/clear` でよい)。Nはループ番号(1〜3)。

| 工程 | コマンド | 成果物 |
|---|---|---|
| 1 執筆/改稿(ライター) | `/writer N` | loops/loopN/作品.md |
| 2 指摘(エディタ) | `/editor N` | loops/loopN/指摘.md |
| 3 調整(オーケストレータ) | `/orchestrator N` | loops/loopN/判断.md(+設定.md・追加指示.md更新) |

手動の場合は各工程後に 進捗.md も自分で更新する。

## 共通

- ループ3のオーケストレータは介入せず、完成宣言と総括のみ(指示書に記載済み)。最終稿 = `loops/loop3/作品.md`
- プロンプトの実体は `.claude/commands/`(コマンド)・`.claude/agents/`(役割定義)・各指示書=すべて固定ファイル(規約の記録義務の対象)。これら以外の入力をした場合は全文を 実行記録.md に残す
