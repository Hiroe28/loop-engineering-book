# 仮審査 手順(人間向け)

entries/ に置かれた作品(本数はラウンドにより異なる)を審査する。※初版の「3本」前提の記述はラウンド1(A/B/C)時代のもの。

## ブラインド化(著者が手作業で行う)

1. 3本を `entries/` にコピーし、`作品X.md`・`作品Y.md`・`作品Z.md` にリネームする(**どの構成をX/Y/Zにするかはランダムに決める**)。中身から構成が分かる記載(ファイル名・改稿注記・不採用理由リスト等)は削っておく ※2026-08-29 実施済み
2. 対応表は**このフォルダの外**(書籍プロジェクト側 `experiment/審査対応表.md`)に置き、**審査が終わるまで審査セッションに見せない**(E1の教訓: 同じフォルダに置くと読まれうる)

## 審査(審査員AI)

### 方法1: 自動実行(推奨)

このフォルダで新規セッション → `/model opus` → `/run-judge`
ディスパッチャが `審査進捗.md` を見ながら、審査員サブエージェント(毎回まっさらな独立コンテキスト=独立採点)を3回起動し、最後に集計係サブエージェントが `審査結果_集計.md` を作って完了する。異常時は停止して報告してくるので、対処後にもう一度 `/run-judge`(進捗の続きから再開)。終了後、`/cost` を 実行記録.md に1回記録する。

### 方法2: 手動実行

- モデルは Opus。**このフォルダで新規セッションを立てて独立に3回**実施し(`/judge 1` → `/clear` → `/judge 2` → `/clear` → `/judge 3`)、平均点で順位を決める(採点のブレ対策)
- 各回、審査員に渡すのは: [審査ルーブリック.md](./審査ルーブリック.md)+`entries/` の3本のみ(どう作られたかは伝えない)
- 審査員への指示(そのまま貼る):

> あなたは文学コンテストの審査員です。審査ルーブリック.md に従い、entries/ の作品X・Y・Zをそれぞれ採点してください。項目ごとに点数(1〜5)と根拠1〜2文、最後に合計点と総評を書いてください。迷ったら低い方の点をつけてください。実在の作家名・作品名には言及しないでください。結果は 審査結果_N.md に保存してください。

- 出力: `審査結果_1.md`〜`審査結果_3.md` → 集計を `審査結果_集計.md`(平均点・順位・講評の要約)

## 審査後

1. 対応表を開き、X/Y/Zがどの構成だったかを記録する
2. 最高得点作を応募候補とし、書籍プロジェクト側の `submission/` で著者が加筆修正する(元テキストと加筆後の両方を保存)
3. 点差・講評の中身は書籍の中核素材(A vs B vs C の差の実証)なので、集計に全文残す
